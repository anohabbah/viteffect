0Basics

Start here. Three ideas carry the whole library: an Effect is a lazy description, its type records what it returns, how it can fail and what it needs, and you compose small effects into bigger ones before running them once.

If Effect.sync or Effect.promise throws or rejects anyway, the failure becomes a defect (an untyped crash), not an E. Use the try* variants for anything that can fail.

Composing: pipe and gen are two styles for the same thing

pipe: a chain of operators. Good for short transformations and for adding retries, timeouts and logging.

Effect.gen: reads like async/await. yield* unwraps an Effect, and a failure exits early the way throw would.

Effect.fn: write functions that return Effects

This is the recommended way to define functions in app code. You get a named span for tracing and stack traces that point to the call site. The optional second argument applies policies like retries or timeouts to the whole function.

1Runtime & fibers

An Effect is a value that describes work. The runtime executes it on a fiber, a lightweight green thread. Fibers form a tree, and that tree is what makes cancellation and cleanup automatic.

Structured concurrency: the fiber tree

main fiber · runPromise(program)
forkChild(worker "fast") → joined ✓

forkChild(worker "slow") → interrupted

When a parent fiber ends, the runtime interrupts any children that are still running. A child fiber can't outlive its parent and leak.

Fork variants

Effect.forkChildchild of the current fiber (default)
Effect.forkScopedlives until the enclosing Scope closes
Effect.forkIn(scope)attached to a specific scope
Effect.forkDetachdaemon fiber, not tied to a parent (use rarely)
Effect.runForkstart from outside Effect, returns a Fiber

Exit and Cause: the result of running a fiber

Exit<A, E>
Success(value: A)

Failure(cause: Cause<E>)
cause.reasons: ReadonlyArray<Reason<E>>
Fail(error: E)
expected error, typed in E
Die(defect: unknown)
bug: a thrown exception or orDie
Interrupt(fiberId)
cancelled

A single failure can have several reasons. For example, the main error plus a finalizer that also crashed, or two parallel branches that both failed. That's why Cause holds a list rather than one error.

Interruption is how cancellation works

Effect.timeout("2 seconds")· Effect.race(a, b)· Fiber.interrupt(f)· parent ends →target fiber gets Interrupt →finalizers run (LIFO)
Interruption is checked between steps. A plain JS await inside tryPromise keeps running unless you pass the provided AbortSignal along: try: (signal) => fetch(url, { signal }). Use Effect.uninterruptible for critical sections that must finish.

2Errors in depth

The rule: if a caller can do something about a failure, make it a typed error in E. If it's a bug or a broken invariant, let it become a defect, and handle defects once at the edge of the app.

3Services & Layers

A service is an interface with a unique key. A layer is a recipe that builds the service. It can depend on other services, acquire resources, and fail. The R type parameter lists services a program still needs. You can only run a program once R = never.

The idiomatic shape (effect-solutions style)

Constructors

Layer.succeed value · Layer.sync lazy value · Layer.effect effectful (and scoped: acquireRelease inside it ties the resource's lifetime to the layer) · Layer.effectDiscard run something on startup, provide nothing

Composition

Layer.provide(dep) feeds a dependency and hides it · Layer.provideMerge(dep) feeds it and also exposes it · Layer.mergeAll(a, b, c) side by side · Layer.fresh opts out of sharing

Graph & memoization

program · R = Users | Config
▲ Effect.provide(AppLayer), once, at the edge
Users.layer · needs Config | HttpClient
▲ fed by
Config.layer · provideMerge (also exposed)
FetchHttpClient.layer · provide (hidden)
Memoization is by reference. If the same layer object appears twice in a graph, it's built once. A function that returns a new layer (Postgres.layer({ url })) creates a new reference on every call, which means two connection pools. Assign the result to a module-level constant and reuse that. Similarly, every separate Effect.provide call builds its own copy, so provide once at the top.

ManagedRuntime: Effect inside a Vite app

A UI has many entry points, such as clicks, route loads and timers. Build the layers once into a runtime and run every entry point through it, so services like the HTTP client and caches are shared.

5Platform: effect/http & effect/http-api

HttpClient: fetch as a service

HttpClient is a service, so you can swap it in tests and decorate it with retries, base URLs or auth headers. In the browser, provide it with FetchHttpClient.layer.

HttpApi: one spec for server, client and OpenAPI

shared/api.ts · HttpApi.make("Api") with groups and endpoints, all described by Schemas
server · HttpApiBuilder.group → handlers
browser · HttpApiClient.make(Api) → typed client
docs · OpenApi / HttpApiScalar / HttpApiSwagger
To serve ApiLive you also need an HttpServer implementation for your runtime, such as the Node or Bun platform packages. effect core provides only the router and the API definition. Because this repo is browser-only (Vite), HttpApiClient and HttpClient are the parts you can use right now.
